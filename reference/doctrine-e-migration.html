Entità, mapping, repository, schema: la scheda da tenere aperta mentre scrivi.

Il modello mentale

Magento 2Oro / Doctrine
ModelEntità: oggetto PHP con dati e dominio, senza persistenza
ResourceModelEntityManager, unico per tutte le entità
CollectionEntityRepository + QueryBuilder (DQL)
db_schema.xmlClassi di migration PHP
$model->save()persist() (solo per i nuovi) + flush()

Unit of Work: un'entità caricata e poi modificata viene salvata al flush() anche senza persist(). persist() serve a far conoscere all'EntityManager un oggetto nuovo.

Attributi di mapping più usati

use Doctrine\DBAL\Types\Types;
use Doctrine\ORM\Mapping as ORM;

#[ORM\Entity(repositoryClass: MyRepository::class)]
#[ORM\Table(name: 'algoritma_my_table')]
#[ORM\UniqueConstraint(name: 'uniq_code', columns: ['code'])]
#[ORM\Index(columns: ['created_at'], name: 'idx_created_at')]
class MyEntity
{
    #[ORM\Column(name: 'id', type: Types::INTEGER)]
    #[ORM\Id]
    #[ORM\GeneratedValue(strategy: 'AUTO')]
    protected ?int $id = null;

    #[ORM\Column(name: 'code', type: Types::STRING, length: 64)]
    protected ?string $code = null;

    #[ORM\Column(name: 'amount', type: Types::DECIMAL, precision: 19, scale: 4, nullable: true)]
    protected $amount;

    #[ORM\Column(name: 'payload', type: Types::JSON, nullable: true)]
    protected ?array $payload = null;

    #[ORM\Column(name: 'created_at', type: Types::DATETIME_MUTABLE)]
    protected ?\DateTime $createdAt = null;

    #[ORM\ManyToOne(targetEntity: OtherEntity::class, inversedBy: 'items')]
    #[ORM\JoinColumn(name: 'other_id', referencedColumnName: 'id', nullable: true, onDelete: 'SET NULL')]
    protected ?OtherEntity $other = null;

    /** @var Collection<int, ChildEntity> */
    #[ORM\OneToMany(mappedBy: 'parent', targetEntity: ChildEntity::class, cascade: ['persist'], orphanRemoval: true)]
    protected Collection $children;
}

Repository e DQL

class MyRepository extends EntityRepository
{
    public function findNeverSynced(int $limit = 50): array
    {
        return $this->createQueryBuilder('m')
            ->where('m.syncedAt IS NULL')
            ->andWhere('m.code LIKE :prefix')
            ->setParameter('prefix', 'ERP-%')
            ->orderBy('m.id', 'ASC')
            ->setMaxResults($limit)
            ->getQuery()
            ->getResult();
    }

    public function countByStatus(string $status): int
    {
        return (int) $this->createQueryBuilder('m')
            ->select('COUNT(m.id)')
            ->where('m.status = :status')
            ->setParameter('status', $status)
            ->getQuery()
            ->getSingleScalarResult();
    }
}

Nel DQL si usano i nomi delle proprietà PHP (m.syncedAt), non i nomi di colonna (synced_at). I nomi di colonna servono nelle migration e nell'SQL nativo.

use Doctrine\Persistence\ManagerRegistry;

// argomento nel services.yml: '@doctrine'
$manager = $this->doctrine->getManagerForClass(MyEntity::class);
$repository = $this->doctrine->getRepository(MyEntity::class);

$manager->persist($entity);   // solo per oggetti nuovi

$manager->remove($entity);

Migration

// Migrations/Schema/AlgoritmaTrainingBundleInstaller.php — installazione da zero
class AlgoritmaTrainingBundleInstaller implements Installation
{
    public function getMigrationVersion(): string { return 'v1_1'; }

    public function up(Schema $schema, QueryBag $queries): void
    {
        $table = $schema->createTable('algoritma_erp_mapping');
        $table->addColumn('id', 'integer', ['autoincrement' => true]);
        $table->addColumn('erp_code', 'string', ['length' => 64]);
        $table->addColumn('synced_at', 'datetime', ['notnull' => false]);
        $table->setPrimaryKey(['id']);
        $table->addUniqueIndex(['erp_code'], 'uniq_algoritma_erp_code');
    }
}

// Migrations/Schema/v1_1/AddStatusColumn.php — modifica incrementale
class AddStatusColumn implements Migration

RegolaPerché
Mai doctrine:schema:updateAllinea solo il database su cui gira: gli ambienti divergono
Installer e migration vanno tenuti allineatiInstallazione pulita e upgrade devono arrivare allo stesso schema
Una migration già eseguita non si modificaOro ricorda cosa ha eseguito: la modifica non verrà mai applicata
Le query di dati vanno in QueryBagEseguite nell'ordine giusto rispetto alle modifiche di schema

Comandi

# elenca le migration che verrebbero eseguite
orobox console oro:migration:load --dry-run

# esegue (senza --force non fa nulla: è una sicurezza)
orobox console oro:migration:load --force

# mostra l'SQL generato
orobox console oro:migration:load --force --show-queries

# limita a un bundle
orobox console oro:migration:load --force --bundles=AlgoritmaTrainingBundle

# carica le fixture di dati
orobox console oro:migration:data:load

# stampa lo schema esistente come codice di migration
orobox console oro:migration:dump

# query SQL diretta, utile per verificare
orobox console doctrine:query:sql "SELECT * FROM algoritma_erp_mapping"

# dopo aver cambiato attributi di entity config
orobox console oro:entity-extend:update-config
orobox console oro:entity-extend:update-schema
