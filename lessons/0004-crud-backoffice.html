Formazione OroCommerce · Lezione 04

Pagine di back-office

Rotte con attributi, controller come servizio, form type e il template Twig che ti regala mezza interfaccia.

Durata: ~70 min Prerequisiti: Lezione 3 Obiettivo: creare e modificare un record dal browser

Perché si parte da qui

La mappatura ERP della lezione 3 oggi la può creare solo un comando di console. Nel progetto reale la deve poter correggere un utente: un codice sbagliato, un allineamento saltato. Serve una pagina. Ed è l'occasione per incontrare quattro pezzi di Symfony in un colpo solo — routing, controller, form, Twig — tutti nella variante che usa Oro, che non è sempre quella dei tutorial.

Il giro completo di una richiesta

Browser
  └─ Router            legge routing.yml e gli attributi #[Route]  → quale controller
      └─ Controller    è un servizio; costruisce il form, delega il salvataggio
          └─ Form      FormType: descrive i campi; valida; scrive sull'entità
              └─ Twig  template che estende un layout Oro già pronto

Uno: dichiarare le rotte

Oro carica le rotte da Resources/config/oro/routing.yml. Il file non elenca le singole rotte: dice al router di leggere gli attributi dei controller del bundle. Forma esatta usata dal core (CronBundle):

algoritma_training:
    resource: "@AlgoritmaTrainingBundle/Controller"
    type:     attribute
    prefix:   /algoritma/erp-mapping

Da lì in poi ogni #[Route] nei controller di quel bundle è attivo, con il prefisso applicato.

Due: il controller è un servizio

Questa è la parte che sorprende chi arriva da Symfony «da tutorial»: in Oro i controller si registrano esplicitamente, in Resources/config/controllers.yml, e sono public. Il container viene iniettato con setContainer e i servizi si dichiarano con getSubscribedServices(): è il pattern service subscriber, che carica un servizio solo quando l'azione lo usa davvero.

# Resources/config/controllers.yml
services:
    _defaults:
        public: true

    Algoritma\Bundle\TrainingBundle\Controller\ErpMappingController:
        calls:
            - ['setContainer', ['@Psr\Container\ContainerInterface']]
        tags:
            - { name: container.service_subscriber }

E l'Extension del bundle deve caricare anche questo file:

$loader->load('services.yml');
$loader->load('controllers.yml');

Modello nel core: vendor/oro/platform/src/Oro/Bundle/DigitalAssetBundle/Resources/config/controllers.yml e .../Controller/DigitalAssetController.php. Vale la pena aprirli in parallelo alla pratica: è il CRUD Oro più corto che si trovi.

Tre: il salvataggio non lo scrivi tu

Oro ha un servizio che gestisce il ciclo «mostra form → intercetta POST → valida → salva → messaggio → redirect»: Oro\Bundle\FormBundle\Model\UpdateHandlerFacade. Il tuo controller gli passa entità, form e messaggio di successo, e riceve indietro o l'array per il template o una RedirectResponse. Non scrivere a mano handleRequest/isValid/flush: perderesti il comportamento standard delle pagine Oro (pulsanti «salva e chiudi», widget in dialog, messaggi flash).

Pratica: creare e modificare una mappatura

  1. Il form type. Form/Type/ErpMappingType.php:

    <?php

declare(strict_types=1);

namespace Algoritma\Bundle\TrainingBundle\Form\Type;

use Algoritma\Bundle\TrainingBundle\Entity\ErpMapping;
use Symfony\Component\Form\AbstractType;
use Symfony\Component\Form\Extension\Core\Type\TextType;
use Symfony\Component\Form\FormBuilderInterface;
use Symfony\Component\OptionsResolver\OptionsResolver;

class ErpMappingType extends AbstractType
{
    #[\Override]
    public function buildForm(FormBuilderInterface $builder, array $options): void
    {
        $builder
            ->add('erpCode', TextType::class, [
                'label' => 'Codice ERP',
                'required' => true,
            ])
            ->add('oroSku', TextType::class, [
                'label' => 'SKU Oro',
                'required' => true,
            ]);
    }

    #[\Override]
    public function configureOptions(OptionsResolver $resolver): void
    {
        $resolver->setDefaults([
            'data_class' => ErpMapping::class,
            'csrf_token_id' => 'algoritma_erp_mapping',
        ]);
    }

    #[\Override]
    public function getBlockPrefix(): string
    {
        return 'algoritma_erp_mapping';
    }
}

    Il form scrive direttamente sull'entità grazie a data_class: i nomi dei campi corrispondono alle proprietà, e Symfony usa i getter e setter che hai scritto nella lezione 3.

  2. Il controller. Controller/ErpMappingController.php:

    <?php

declare(strict_types=1);

namespace Algoritma\Bundle\TrainingBundle\Controller;

use Algoritma\Bundle\TrainingBundle\Entity\ErpMapping;
use Algoritma\Bundle\TrainingBundle\Form\Type\ErpMappingType;
use Oro\Bundle\FormBundle\Model\UpdateHandlerFacade;
use Symfony\Bridge\Twig\Attribute\Template;
use Symfony\Bundle\FrameworkBundle\Controller\AbstractController;
use Symfony\Component\HttpFoundation\RedirectResponse;
use Symfony\Component\Routing\Attribute\Route;

class ErpMappingController extends AbstractController
{
    #[Route(path: '/create', name: 'algoritma_erp_mapping_create')]
    #[Template('@AlgoritmaTraining/ErpMapping/update.html.twig')]
    public function createAction(): array|RedirectResponse
    {
        return $this->update(new ErpMapping());
    }

    #[Route(path: '/update/{id}', name: 'algoritma_erp_mapping_update', requirements: ['id' => '\d+'])]
    #[Template('@AlgoritmaTraining/ErpMapping/update.html.twig')]
    public function updateAction(ErpMapping $erpMapping): array|RedirectResponse
    {
        return $this->update($erpMapping);
    }

    private function update(ErpMapping $erpMapping): array|RedirectResponse
    {
        return $this->container->get(UpdateHandlerFacade::class)->update(
            $erpMapping,
            $this->createForm(ErpMappingType::class, $erpMapping),
            'Mappatura ERP salvata'
        );
    }

    #[\Override]
    public static function getSubscribedServices(): array
    {
        return array_merge(parent::getSubscribedServices(), [
            UpdateHandlerFacade::class,
        ]);
    }
}

    Due cose da notare. updateAction(ErpMapping $erpMapping): Symfony converte automaticamente l'{id} della rotta nell'entità (entity value resolver), e risponde 404 se non esiste. E il nome del template, @AlgoritmaTraining/...: la scorciatoia Twig per Resources/views/ del bundle, con il suffisso Bundle tolto dal nome.

  3. Il template. Resources/views/ErpMapping/update.html.twig:

    {% extends '@OroUI/actions/update.html.twig' %}

{% set formAction = form.vars.value.id
    ? path('algoritma_erp_mapping_update', { id: form.vars.value.id })
    : path('algoritma_erp_mapping_create')
%}

{% block pageHeader %}
    <h1>{{ form.vars.value.id ? 'Modifica mappatura ERP' : 'Nuova mappatura ERP' }}</h1>
{% endblock %}

    Tre righe di tuo e hai l'intestazione, i pulsanti di salvataggio, la gestione degli errori e lo stile del back-office, perché @OroUI/actions/update.html.twig fa tutto il resto. È lo stesso layout che estendono i controller del core.

  4. Registra rotte, controller e form type.

    # Resources/config/oro/routing.yml
algoritma_training:
    resource: "@AlgoritmaTrainingBundle/Controller"
    type:     attribute
    prefix:   /algoritma/erp-mapping
    # Resources/config/services.yml — sotto _defaults
    Algoritma\Bundle\TrainingBundle\Form\Type\ErpMappingType:
        tags:
            - { name: form.type }

    Più controllers.yml come sopra, e il suo $loader->load('controllers.yml') nell'Extension.

  5. Prova.

    orobox console cache:clear
orobox console debug:router | grep algoritma

    Atteso: due rotte, algoritma_erp_mapping_create e algoritma_erp_mapping_update, con i loro percorsi. Poi apri https://<dominio>:<porta>/admin/algoritma/erp-mapping/create (l'URL base è quello stampato da orobox up), compila e salva.

    Dopo il salvataggio, verifica dal database che il record ci sia:

    orobox console doctrine:query:sql "SELECT * FROM algoritma_erp_mapping"

La vittoria di oggi

Un utente non tecnico può creare e correggere una mappatura ERP dal back-office. Hai scritto un form type, un controller di venti righe e un template di tre: tutto il resto — layout, pulsanti, validazione, messaggi — te lo ha dato la piattaforma.

Verifica: rispondi a memoria

Cosa contiene tipicamente il file routing.yml di un bundle Oro?

Il file punta a @NomeBundle/Controller con type: attribute: le singole rotte stanno negli attributi #[Route] dei metodi, e il prefix del file si applica a tutte.

Perché un controller Oro dichiara getSubscribedServices?

È il pattern service subscriber: il controller dichiara cosa potrebbe servirgli e il container glielo fornisce pigramente, invece di costruire tutte le dipendenze a ogni richiesta.

Chi salva l'entità quando l'utente invia il form?

UpdateHandlerFacade::update() gestisce submit, validazione, flush, messaggio flash e redirect. Il form type descrive solo i campi.

Cosa indica il nome di template @AlgoritmaTraining/ErpMapping/update.html.twig?

La chiocciola indica il namespace Twig del bundle, che punta a Resources/views/. Nel nome logico il suffisso Bundle si omette.

A memoria: i quattro file (oltre all'entità) che hai toccato per avere una pagina funzionante, e cosa contiene ciascuno.

oro/routing.yml punta alla cartella Controller · controllers.yml registra il controller come servizio pubblico con container.service_subscriber · Form/Type/ErpMappingType.php descrive i campi e la data_class · Resources/views/ErpMapping/update.html.twig estende @OroUI/actions/update.html.twig.

Ripasso dalla lezione 3 (spaziatura): perché non si usa doctrine:schema:update in Oro?

Perché lo schema è governato dalle migration, che Oro esegue in ordine e registra: sono l'unico modo per far arrivare tutti gli ambienti allo stesso stato in modo ripetibile. schema:update allinea solo il database su cui lo lanci.

Da leggere prima della prossima lezione

Fonte primaria

Symfony — Forms, fino a «Validating Forms» compreso. Salta la parte su form senza classe di dati: in Oro il form è quasi sempre legato a un'entità tramite data_class.

Poi apri, come esempio reale da imitare, vendor/oro/platform/src/Oro/Bundle/DigitalAssetBundle/Controller/DigitalAssetController.php. Leggere il core è una competenza del mestiere, non un extra.

Esercizio fra una sessione e l'altra

  1. Aggiungi al form il campo syncedAt con Oro\Bundle\FormBundle\Form\Type\OroDateTimeType e 'required' => false. Verifica che il valore si salvi.
  2. Aggiungi una validazione: #[Assert\NotBlank] e #[Assert\Length(max: 64)] sulla proprietà erpCode dell'entità (use Symfony\Component\Validator\Constraints as Assert;). Prova a salvare vuoto e guarda l'errore comparire nella pagina, senza aver scritto una riga di gestione errori.
  3. Domanda da girarmi con la tua risposta: se in Magento avresti messo questa logica in un Ui Component XML, dove finisce in Oro? Prova a rispondere prima di chiedere.
