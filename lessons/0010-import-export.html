Import ed export

Il canale dei volumi grandi: processori, data converter, strategie — e un CSV che diventa righe nel database.

Durata: ~75 min Prerequisiti: Lezione 9 Obiettivo: importare un CSV nella tua entità

Perché si parte da qui

L'API va bene per gli aggiornamenti puntuali. Quando l'ERP ti manda 80.000 righe di anagrafica ogni notte, serve un canale progettato per i lotti: transazioni a blocchi, validazione separata dal salvataggio, log degli errori riga per riga, esecuzione in background. In Oro questo canale è l'import/export, ed è costruito sopra un motore di job batch.

I quattro pezzi, e cosa fa ciascuno

PezzoResponsabilitàLo scrivi tu?
ReaderLegge il file riga per riga (CSV in genere)Quasi mai
Data converterTraduce le intestazioni del file nei campi dell'entitàSpesso: di solito configurando, non programmando
ProcessorTrasforma la riga in un oggetto e lo passa alla strategiaA volte
StrategyDecide se creare o aggiornare, valida, gestisce le relazioniQuando la logica è tua

Tutti e quattro si dichiarano in Resources/config/importexport.yml — un file separato da services.yml, caricato dall'Extension del bundle — e si registrano con il tag oro_importexport.processor.

    oro_product.importexport.processor.import.product:
        parent: oro_importexport.processor.import_abstract
        calls:
            - [setDataConverter, ['@oro_product.importexport.data_converter.product']]
            - [setStrategy, ['@oro_product.importexport.strategy.product']]
        tags:
            - { name: oro_importexport.processor, type: import, entity: 'Oro\Bundle\ProductBundle\Entity\Product', alias: oro_product_product.add_or_replace }
            - { name: oro_importexport.processor, type: import_validation, entity: 'Oro\Bundle\ProductBundle\Entity\Product', alias: oro_product_product.add_or_replace }

Sorgente: vendor/oro/commerce/src/Oro/Bundle/ProductBundle/Resources/config/importexport.yml. Nota i quattro valori possibili di type: import, import_validation, export, export_template. Il secondo è l'anteprima che l'utente vede prima di confermare: si dichiara sempre insieme al primo.

La scorciatoia che userai quasi sempre

Per un'entità semplice non serve scrivere PHP: bastano i servizi «configurabili» del core più la configurazione dei campi sull'entità.

    # data converter generico: usa la configurazione dell'entità
    algoritma_training.importexport.data_converter:
        parent: oro_importexport.data_converter.configurable

    # strategia generica: crea o aggiorna in base ai campi "identity"
    algoritma_training.importexport.strategy:
        parent: oro_importexport.strategy.configurable_add_or_replace

Il pezzo che manca è dire a Oro quale campo identifica una riga: si fa con l'attributo #[ConfigField] sull'entità.

#[ORM\Column(name: 'erp_code', type: Types::STRING, length: 64)]
#[ConfigField(defaultValues: ['importexport' => ['identity' => true]])]
protected ?string $erpCode = null;

#[ORM\Column(name: 'synced_at', type: Types::DATETIME_MUTABLE, nullable: true)]
#[ConfigField(defaultValues: ['importexport' => ['excluded' => true]])]
protected ?\DateTime $syncedAt = null;

Tre opzioni da ricordare: identity (per riconoscere un record esistente), excluded (campo che non entra e non esce), order (posizione della colonna nel file). Esempio reale: vendor/oro/platform/src/Oro/Bundle/UserBundle/Entity/User.php, proprietà username e usernameLowercase.

Pratica: importare le mappature da CSV

  1. Marca i campi sull'entità. Aggiungi use Oro\Bundle\EntityConfigBundle\Metadata\Attribute\ConfigField; e gli attributi come sopra: erpCode come identity, syncedAt come excluded.

  2. Dichiara i servizi. src/Algoritma/Bundle/TrainingBundle/Resources/config/importexport.yml:

    services:
    algoritma_training.importexport.data_converter:
        parent: oro_importexport.data_converter.configurable

    algoritma_training.importexport.strategy:
        parent: oro_importexport.strategy.configurable_add_or_replace

    algoritma_training.importexport.processor.import:
        parent: oro_importexport.processor.import_abstract
        calls:
            - [setDataConverter, ['@algoritma_training.importexport.data_converter']]
            - [setStrategy, ['@algoritma_training.importexport.strategy']]
        tags:
            - { name: oro_importexport.processor, type: import, entity: 'Algoritma\Bundle\TrainingBundle\Entity\ErpMapping', alias: algoritma_erp_mapping.add_or_replace }
            - { name: oro_importexport.processor, type: import_validation, entity: 'Algoritma\Bundle\TrainingBundle\Entity\ErpMapping', alias: algoritma_erp_mapping.add_or_replace }

    algoritma_training.importexport.processor.export:
        parent: oro_importexport.processor.export_abstract
        calls:
            - [setDataConverter, ['@algoritma_training.importexport.data_converter']]
        tags:
            - { name: oro_importexport.processor, type: export, entity: 'Algoritma\Bundle\TrainingBundle\Entity\ErpMapping', alias: algoritma_erp_mapping }

  3. Carica il file dall'Extension. In DependencyInjection/AlgoritmaTrainingExtension.php:

    $loader->load('importexport.yml');

  4. Prepara il CSV. Le intestazioni corrispondono ai nomi delle proprietà dell'entità. Il file deve stare dentro la cartella del progetto: il comando gira nel container, e /tmp del tuo portatile lì non esiste.

    cat > var/mappings.csv <<'CSV'
erpCode,oroSku
ERP-2001,SKU-201
ERP-2002,SKU-202
CSV

  5. Valida prima di importare. Sempre, anche in produzione: è gratis e ti risparmia i rollback.

    orobox console cache:clear
orobox console oro:import:file var/mappings.csv \
  --jobName=entity_import_validation_from_csv \
  --processor=algoritma_erp_mapping.add_or_replace \
  --email=admin@example.com \
  --validation

    Due dettagli che fanno perdere tempo se non li sai, verificati eseguendo il comando su un'installazione 7.0 CE: --email è obbligatorio (è l'indirizzo a cui arriva il report), e il job della validazione è entity_import_validation_from_csv, diverso da quello dell'import. Se sbagli job, il comando ti mostra l'elenco di quelli disponibili.

  6. Importa. Job diverso, niente --validation:

    orobox console oro:import:file var/mappings.csv \
  --jobName=entity_import_from_csv \
  --processor=algoritma_erp_mapping.add_or_replace \
  --email=admin@example.com

    Risposta attesa: Scheduled successfully. The result will be sent to the email.

  7. Fai girare il consumer. Ed è la cosa più importante di questa lezione: l'import non viene eseguito dal comando. Il comando mette un messaggio in coda; il lavoro lo fa il consumer. Senza consumer attivo non succede niente, e non è un errore.

    orobox console oro:message-queue:consume

    Lascialo girare qualche secondo, poi fermalo con Ctrl+C e verifica:

    orobox console doctrine:query:sql "SELECT id, erp_code, oro_sku FROM algoritma_erp_mapping ORDER BY id"

    Le due righe del CSV devono esserci. È la lezione 11 che arriva in anticipo: import, export e metà della piattaforma girano sulla message queue.

  8. Prova l'idempotenza. Cambia SKU-201 in SKU-999 nel CSV, reimporta e fai girare di nuovo il consumer. Grazie a identity su erpCode, la riga deve essere aggiornata, non duplicata: stesso id, oro_sku nuovo. Se ti ritrovi due righe, l'attributo #[ConfigField] non è stato applicato: serve cache:clear e, in alcuni casi, orobox console oro:entity-extend:update-config.

La vittoria di oggi

Hai un canale di caricamento massivo idempotente, con validazione separata, senza aver scritto una riga di PHP oltre a due attributi sull'entità. Nei progetti ERP questo è il canale che regge il grosso del traffico notturno.

Quando serve scrivere codice davvero

EsigenzaDove metti le mani
Le intestazioni del file non corrispondono ai campiData converter proprio, che estende quello configurabile
Servono valori derivati o normalizzati (date, valute)Processor proprio, o un normalizer dedicato
«Se il record esiste ed è in stato X, non aggiornarlo»Strategy propria, che estende configurable_add_or_replace
Relazioni verso altre entità da risolvere per codiceStrategy: è lì che si cercano gli oggetti collegati

Modello completo da imitare quando arriverai a questo punto: Oro\Bundle\ProductBundle\ImportExport\Processor\ProductImportProcessor e le sue strategie, nel commerce.

Verifica: rispondi a memoria

Cosa fa la strategy in un import Oro?

Reader legge, data converter traduce le intestazioni, processor costruisce l'oggetto, strategy decide creazione o aggiornamento (in base ai campi identity), valida e risolve le relazioni.

Come dichiari il campo che identifica una riga?

#[ConfigField(defaultValues: ['importexport' => ['identity' => true]])]. L'indice unico è una buona idea in ogni caso, ma è il database: non è quello che guarda la strategia.

Perché si dichiara anche il tipo import_validation?

È il passaggio che l'interfaccia (e l'opzione --validation) usa per dire all'utente cosa succederà, senza scrivere nulla. Il template di esempio è invece export_template.

Quale job name usa l'import generico da CSV?

entity_import_from_csv per l'import, entity_import_validation_from_csv per la sola validazione, entity_export_to_csv per l'export. Sono definiti in batch_jobs.yml dell'ImportExportBundle: quando un progetto ha esigenze particolari, si definiscono job propri lì.

A memoria: i quattro pezzi della catena di import, in ordine, con una riga ciascuno.

Reader (legge il file) → data converter (intestazioni → campi) → processor (riga → oggetto) → strategy (crea o aggiorna, valida, risolve relazioni).

Ripasso dalla lezione 9 (spaziatura): perché non esporresti mai le mappature ERP sulla storefront API?

Perché quel canale è per i clienti del negozio (customer user ed eventualmente ospiti): sono dati interni di integrazione, e l'errore si paga come fuga di dati, non come bug.

Da leggere prima della prossima lezione

Fonte primaria

Oro — Integrations, sezione Import and Export. Poi, più utile della documentazione: vendor/oro/platform/src/Oro/Bundle/UserBundle/Resources/config/importexport.yml, che è l'esempio completo più corto del core.

Esercizio fra una sessione e l'altra

  1. Aggiungi export_template (un processore con oro_importexport.data_converter.template_fixture.configurable, come fa UserBundle) e scarica il template: è il modo giusto per scoprire le intestazioni attese invece di indovinarle.
  2. Registra un oro_importexport.configuration provider per la tua entità (sempre modello UserBundle) così che i pulsanti di import ed export compaiano sopra la griglia della lezione 5.
  3. Prova un CSV sporco: una riga senza oroSku, una con un codice ERP duplicato. Lancia con --validation e leggi il report. Poi dimmi cosa faresti, in un progetto reale, con le righe scartate — è una decisione di progetto, non tecnica.
