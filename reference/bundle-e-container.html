Bundle e service container

Scheda di consultazione rapida: struttura di un bundle, sintassi di services.yml, comandi di diagnosi.

Oro 7.0 · Symfony 7.4 Verificato su Oro 7.0 CE Nasce dalla Lezione 2

Creare un bundle

orobox create bundle 'Algoritma\Bundle\TrainingBundle'
orobox console cache:clear

Gli apici singoli sono obbligatori: proteggono i backslash dalla shell. Il bundle finisce in src/<Namespace>/, già in autoload PSR-4 (composer.json: "psr-4": {"": "src/"}).

bundles.yml: la dichiarazione al kernel

bundles:
    - { name: Algoritma\Bundle\TrainingBundle\AlgoritmaTrainingBundle, priority: 30 }
  • Il kernel Oro scandisce src/ e vendor/ e registra ogni bundle che dichiara questo file. Non esiste un elenco centrale da editare.
  • Ordinamento per priorità crescente; a parità di priorità, alfabetico. Numero più basso = caricato prima.
  • Il core usa priorità negative (OroUIBundle: -120). Il codice di progetto sta dopo, ed è ciò che permette di sovrascrivere risorse del core.
  • Sorgente della verità: vendor/oro/platform/src/Oro/Bundle/DistributionBundle/OroKernel.php (collectBundles, findBundles, compareBundles).

services.yml: sintassi essenziale

services:
    _defaults:
        autowire: false         # ogni argomento va dichiarato
        autoconfigure: false    # ogni tag va scritto a mano
        public: false           # i servizi si ottengono per injection

    Algoritma\Bundle\TrainingBundle\Provider\GreetingProvider:
        arguments:
            - '%kernel.environment%'        # parametro del container
            - '@logger'                     # altro servizio
            - 'valore letterale'            # stringa

    Algoritma\Bundle\TrainingBundle\Command\HelloCommand:
        arguments:
            - '@Algoritma\Bundle\TrainingBundle\Provider\GreetingProvider'
        tags:
            - { name: console.command }

    # alias: un secondo nome per lo stesso servizio
    Algoritma\Bundle\TrainingBundle\Provider\GreetingProviderInterface:
        alias: Algoritma\Bundle\TrainingBundle\Provider\GreetingProvider
SintassiSignificato
'@servizio'Riferimento a un altro servizio
'@?servizio'Riferimento opzionale: null se il servizio non esiste
'%parametro%'Valore di un parametro del container
'%%'Percentuale letterale (escape)
tags:Iscrive il servizio a un meccanismo del framework
alias:Secondo id per lo stesso servizio
decorates:Sostituisce un servizio esistente incapsulandolo
calls:Setter chiamati dopo la costruzione
lazy: trueIstanzia il servizio solo al primo uso reale

Id dei servizi: nel codice nuovo si usa il FQCN della classe. Gli id a punti (oro_cron.cron_helper) sono legacy di vendor/oro: vanno riconosciuti, non imitati.

Tag che incontrerai più spesso

TagA cosa serve
console.commandRegistra un comando di console
kernel.event_listenerAscolta un evento (richiede event e method)
kernel.event_subscriberLa classe dichiara da sé gli eventi che ascolta
doctrine.event_listenerAggancia gli eventi del ciclo di vita Doctrine
twig.extensionAggiunge funzioni e filtri Twig
oro_message_queue.client.message_processorProcessore di coda (message queue)
oro_importexport.processorProcessore di import/export

Per scoprire i tag disponibili e chi li usa: orobox console debug:container --tags, oppure orobox console debug:container --tag=console.command.

Comandi di diagnosi

# bundle registrati
orobox console debug:container --parameter=kernel.bundles --format=json | grep Training

# scheda di un servizio: argomenti, tag, chi lo usa
orobox console debug:container 'Algoritma\Bundle\TrainingBundle\Provider\GreetingProvider'

# cercare per frammento di id
orobox console debug:container greeting

# tutti i servizi con un certo tag
orobox console debug:container --tag=console.command

# tutti i parametri del container
orobox console debug:container --parameters

# eventi e listener registrati
orobox console debug:event-dispatcher

# rotte
orobox console debug:router

# dopo ogni modifica a YAML, attributi di mapping o configurazione
orobox console cache:clear
