Entità e migration

Doctrine ORM al posto di Model / ResourceModel / Collection, e una migration che crea davvero la tabella.

Durata: ~70 min Prerequisiti: Lezione 2 Obiettivo: tabella creata, record letto e scritto

Perché si parte da qui

Un'integrazione ERP ha bisogno di posti dove mettere i dati: mappature di codici, stati di sincronizzazione, code di record da riconciliare. Tutto questo sono entità. È anche il punto in cui il tuo modello mentale Magento va riscritto di più, quindi vale la pena farlo adesso, su una entità piccola e tua, e non fra due mesi su quella del cliente.

Il salto concettuale da Magento

Magento 2Oro / Doctrine
Model (dati + logica + persistenza)Entità: solo dati e comportamento di dominio. Non sa salvarsi.
ResourceModelEntityManager: gestisce persist / flush / remove per tutte le entità.
CollectionEntityRepository + QueryBuilder (DQL).
etc/db_schema.xmlClasse di migration PHP in Migrations/Schema/.
setup:upgradeoro:migration:load --force
Repository + interfacce di servizioRepository Doctrine, ottenuto dal ManagerRegistry.

La differenza che conta davvero

Doctrine è un Data Mapper con Unit of Work: tu modifichi oggetti PHP normali, e al flush() Doctrine calcola le query necessarie. Non esiste $model->save(). Non esiste $collection->load(). Un oggetto caricato e poi modificato viene salvato al flush() anche se non chiami persist(): persist() serve solo per gli oggetti nuovi.

Come si dichiara un'entità in Oro 7.0

Mapping con attributi PHP (le annotation sono superate). Questa è la forma che trovi nel core — l'esempio sotto ricalca vendor/oro/platform/src/Oro/Bundle/EmailBundle/Entity/EmailFolder.php:

#[ORM\Entity]
#[ORM\Table(name: 'algoritma_erp_mapping')]
class ErpMapping
{
    #[ORM\Column(name: 'id', type: Types::INTEGER)]
    #[ORM\Id]
    #[ORM\GeneratedValue(strategy: 'AUTO')]
    protected ?int $id = null;

    #[ORM\Column(name: 'erp_code', type: Types::STRING, length: 64)]
    protected ?string $erpCode = null;
}

Oro aggiunge un attributo suo, #[Config] (Oro\Bundle\EntityConfigBundle\Metadata\Attribute\Config), che registra l'entità nel sistema di entity config: icona, ownership, possibilità di aggiungere campi da interfaccia, comportamento verso audit e attività. Senza #[Config] l'entità esiste per Doctrine ma resta invisibile ai meccanismi Oro.

Esempio reale minimo nel core: vendor/oro/platform/src/Oro/Bundle/AddressBundle/Entity/Address.php — #[ORM\Entity], #[ORM\Table('oro_address')] e #[Config(defaultValues: [...])].

La migration: lo schema è codice

Doctrine sa generare lo schema dalle entità, ma in Oro non si usa mai doctrine:schema:update. Lo schema si dichiara in classi di migration, che Oro esegue in ordine e registra in tabella, così ogni ambiente arriva allo stesso stato.

Due tipi di classe:

  • Installer (implements Installation): crea lo schema da zero per un'installazione nuova, e dichiara a quale versione corrisponde con getMigrationVersion().
  • Migration (implements Migration), in cartelle v1_0, v1_1, …: modifica incrementale per chi ha già la versione precedente.

Modello reale nel core: vendor/oro/platform/src/Oro/Bundle/CronBundle/Migrations/Schema/OroCronBundleInstaller.php (installer) e .../Migrations/Schema/v1_3/OroCronBundle.php (migration incrementale).

Regola pratica di progetto

Finché il progetto non è in produzione puoi tenere solo l'installer e ricreare il database. Dal primo deploy in poi, ogni modifica di schema è una nuova classe in una nuova cartella vN_M, e l'installer si aggiorna per restare allineato. Se modifichi una migration già eseguita in produzione, quella modifica non verrà mai applicata: Oro ricorda cosa ha già eseguito.

Pratica: un'entità di mappatura ERP

Costruiamo qualcosa che userai davvero: una tabella che associa l'identificativo di un prodotto nell'ERP al prodotto Oro, con la data dell'ultima sincronizzazione.

  1. L'entità. src/Algoritma/Bundle/TrainingBundle/Entity/ErpMapping.php:

    <?php

declare(strict_types=1);

namespace Algoritma\Bundle\TrainingBundle\Entity;

use Doctrine\DBAL\Types\Types;
use Doctrine\ORM\Mapping as ORM;
use Oro\Bundle\EntityConfigBundle\Metadata\Attribute\Config;

#[ORM\Entity(repositoryClass: ErpMappingRepository::class)]
#[ORM\Table(name: 'algoritma_erp_mapping')]
#[ORM\UniqueConstraint(name: 'uniq_algoritma_erp_code', columns: ['erp_code'])]
#[Config(defaultValues: ['entity' => ['icon' => 'fa-exchange']])]
class ErpMapping
{
    #[ORM\Column(name: 'id', type: Types::INTEGER)]
    #[ORM\Id]
    #[ORM\GeneratedValue(strategy: 'AUTO')]
    protected ?int $id = null;

    #[ORM\Column(name: 'erp_code', type: Types::STRING, length: 64)]
    protected ?string $erpCode = null;

    #[ORM\Column(name: 'oro_sku', type: Types::STRING, length: 255)]
    protected ?string $oroSku = null;

    #[ORM\Column(name: 'synced_at', type: Types::DATETIME_MUTABLE, nullable: true)]
    protected ?\DateTime $syncedAt = null;

    public function getId(): ?int
    {
        return $this->id;
    }

    public function getErpCode(): ?string
    {
        return $this->erpCode;
    }

    public function setErpCode(string $erpCode): self
    {
        $this->erpCode = $erpCode;

        return $this;
    }

    public function getOroSku(): ?string
    {
        return $this->oroSku;
    }

    public function setOroSku(string $oroSku): self
    {
        $this->oroSku = $oroSku;

        return $this;
    }

    public function getSyncedAt(): ?\DateTime
    {
        return $this->syncedAt;
    }

    public function setSyncedAt(?\DateTime $syncedAt): self
    {
        $this->syncedAt = $syncedAt;

        return $this;
    }
}

  2. Il repository. src/Algoritma/Bundle/TrainingBundle/Entity/ErpMappingRepository.php:

    <?php

declare(strict_types=1);

namespace Algoritma\Bundle\TrainingBundle\Entity;

use Doctrine\ORM\EntityRepository;

/**
 * @extends EntityRepository<ErpMapping>
 */
class ErpMappingRepository extends EntityRepository
{
    public function findByErpCode(string $erpCode): ?ErpMapping
    {
        return $this->findOneBy(['erpCode' => $erpCode]);
    }

    /**
     * @return ErpMapping[]
     */
    public function findNeverSynced(int $limit = 50): array
    {
        return $this->createQueryBuilder('m')
            ->where('m.syncedAt IS NULL')
            ->orderBy('m.id', 'ASC')
            ->setMaxResults($limit)
            ->getQuery()
            ->getResult();
    }
}

    Nota createQueryBuilder('m'): i campi si nominano con il nome della proprietà PHP (m.syncedAt), non con il nome della colonna (synced_at). È DQL, non SQL.

  3. L'installer. src/Algoritma/Bundle/TrainingBundle/Migrations/Schema/AlgoritmaTrainingBundleInstaller.php:

    <?php

declare(strict_types=1);

namespace Algoritma\Bundle\TrainingBundle\Migrations\Schema;

use Doctrine\DBAL\Schema\Schema;
use Oro\Bundle\MigrationBundle\Migration\Installation;
use Oro\Bundle\MigrationBundle\Migration\QueryBag;

class AlgoritmaTrainingBundleInstaller implements Installation
{
    #[\Override]
    public function getMigrationVersion(): string
    {
        return 'v1_0';
    }

    #[\Override]
    public function up(Schema $schema, QueryBag $queries): void
    {
        if ($schema->hasTable('algoritma_erp_mapping')) {
            return;
        }

        $table = $schema->createTable('algoritma_erp_mapping');
        $table->addColumn('id', 'integer', ['autoincrement' => true]);
        $table->addColumn('erp_code', 'string', ['length' => 64]);
        $table->addColumn('oro_sku', 'string', ['length' => 255]);
        $table->addColumn('synced_at', 'datetime', ['notnull' => false]);
        $table->setPrimaryKey(['id']);
        $table->addUniqueIndex(['erp_code'], 'uniq_algoritma_erp_code');
    }
}

    Nella migration usi i nomi di colonna e i tipi DBAL: qui sei al livello del database, non dell'ORM. I due livelli devono combaciare a mano — nessuno lo verifica per te.

  4. Esegui.

    orobox console cache:clear
orobox console oro:migration:load --dry-run
orobox console oro:migration:load --force

    --dry-run elenca le migration che verrebbero eseguite senza toccare il database. --force è l'interruttore di sicurezza: senza, il comando esce e non fa nulla. Aggiungi --show-queries quando vuoi vedere l'SQL.

  5. Verifica lo schema.

    orobox console doctrine:query:sql "SELECT * FROM algoritma_erp_mapping"

    Atteso: zero righe, nessun errore. Se la tabella non esiste, la migration non è stata raccolta: controlla il percorso Migrations/Schema/ dentro il bundle.

  6. Scrivi e leggi dal codice. Estendi il comando della lezione 2 — o creane uno nuovo, Command/ErpMappingDemoCommand.php:

    <?php

declare(strict_types=1);

namespace Algoritma\Bundle\TrainingBundle\Command;

use Algoritma\Bundle\TrainingBundle\Entity\ErpMapping;
use Algoritma\Bundle\TrainingBundle\Entity\ErpMappingRepository;
use Doctrine\Persistence\ManagerRegistry;
use Symfony\Component\Console\Attribute\AsCommand;
use Symfony\Component\Console\Command\Command;
use Symfony\Component\Console\Input\InputInterface;
use Symfony\Component\Console\Output\OutputInterface;

#[AsCommand(name: 'algoritma:training:mapping-demo', description: 'Crea e rilegge una mappatura ERP.')]
class ErpMappingDemoCommand extends Command
{
    public function __construct(private ManagerRegistry $doctrine)
    {
        parent::__construct();
    }

    protected function execute(InputInterface $input, OutputInterface $output): int
    {
        $manager = $this->doctrine->getManagerForClass(ErpMapping::class);

        $mapping = new ErpMapping();
        $mapping->setErpCode('ERP-' . random_int(1000, 9999));
        $mapping->setOroSku('SKU-001');

        $manager->persist($mapping);
        $manager->flush();

        /** @var ErpMappingRepository $repository */
        $repository = $this->doctrine->getRepository(ErpMapping::class);
        $output->writeln(sprintf('Creato id=%d, mai sincronizzati: %d',
            $mapping->getId(),
            count($repository->findNeverSynced())
        ));

        return Command::SUCCESS;
    }
}

    Registralo in services.yml con l'argomento '@doctrine' e il tag console.command, poi:

    orobox console cache:clear
orobox console algoritma:training:mapping-demo

    Atteso: Creato id=1, mai sincronizzati: 1. Rilancialo: l'id cresce.

La vittoria di oggi

Hai una tabella creata da una migration tua, un'entità mappata con attributi, un repository con una query DQL, e codice che scrive e rilegge. È il ciclo completo di persistenza: tutto il resto (API, integrazioni, code) non fa che passare dati attraverso questo.

Le tre trappole dei primi giorni

TrappolaCosa succede
Usare doctrine:schema:updateFunziona sul tuo portatile e diverge da tutti gli altri ambienti. In Oro lo schema lo governano le migration.
Dimenticare flush()Nessun errore, nessun dato. persist() registra l'intenzione; flush() esegue.
Nomi colonna nel DQLm.synced_at non esiste: nel DQL si usa il nome della proprietà, m.syncedAt.

Verificato: cancellare un'entità non basta

Provando questa lezione ho creato un'entità con #[Config] e poi ho cancellato il bundle. Risultato: cache:clear si è rotto con Class "…\Entity\SandboxMapping" does not exist, perché l'entità resta registrata nella tabella oro_entity_config. Per ripulire servono tre delete, in quest'ordine: oro_entity_config_index_value (per entity_id e per i field_id di quell'entità), poi oro_entity_config_field, poi oro_entity_config. Morale operativa: in Oro un'entità lascia tracce nel database oltre alla sua tabella. Tienilo presente quando fai pulizia su un progetto reale.

Verifica: rispondi a memoria

Chi salva sul database un'entità Doctrine modificata?

L'entità è un oggetto PHP senza logica di persistenza (Data Mapper). L'EntityManager traccia le modifiche e le scrive al flush(). persist() serve solo a far conoscere all'EntityManager un oggetto nuovo.

Quale comando applica le tue migration al database?

oro:migration:load --force. Senza --force il comando esce senza fare nulla: è una sicurezza voluta. oro:migration:dump stampa lo schema esistente come codice, non lo applica.

In un QueryBuilder, come nomini il campo di data?

Il QueryBuilder produce DQL, che ragiona su entità e proprietà. I nomi di colonna servono solo nelle migration e nell'SQL nativo.

A cosa serve l'attributo Config sull'entità?

#[Config] è di Oro (EntityConfigBundle) e alimenta icona, ownership, audit, campi aggiuntivi da interfaccia. Il repository si dichiara in #[ORM\Entity(repositoryClass: ...)], la tabella in #[ORM\Table].

A memoria: traduci in Oro i tre pezzi Magento — Model, ResourceModel, Collection.

Model → entità (solo dati e dominio) · ResourceModel → EntityManager (unico, per tutte le entità) · Collection → EntityRepository + QueryBuilder (DQL).

Ripasso dalla lezione 2 (spaziatura): cosa serve perché un tuo servizio diventi un comando di console?

Classe che estende Command, attributo #[AsCommand] per nome e descrizione, definizione in services.yml con gli argomenti espliciti e il tag console.command (serve perché autoconfigure è false), poi cache:clear.
