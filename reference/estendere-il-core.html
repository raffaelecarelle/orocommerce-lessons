Albero delle decisioni

Devo cambiare il comportamento di codice in vendor/oro
│
├─ Il core pubblica un evento nel punto giusto?      → EVENTO           (preferito)
│
├─ Il comportamento sta dentro un servizio?          → DECORAZIONE
│
├─ Devo cambiare la definizione di un servizio?      → COMPILER PASS
│
└─ Devo cambiare solo cosa si vede?
   ├─ Esiste un blocco Twig da sovrascrivere?        → EXTENDS + BLOCK
   └─ Altrimenti                                     → OVERRIDE DEL TEMPLATE (ultima scelta)

Non esiste l'equivalente dei plugin Magento

Non puoi intercettare «il metodo X della classe Y» dichiarandolo in un file. Decori un servizio, e ne implementi l'intera interfaccia. Se il codice che vuoi cambiare non è dietro un servizio, quella strada è chiusa.

        arguments:
            - '@logger'
        tags:
            # evento del kernel
            - { name: kernel.event_listener, event: kernel.request, method: onKernelRequest }

            - { name: kernel.event_listener, event: oro_datagrid.datagrid.build.after.users-grid, method: onBuildAfter }
            # priorità: più alto = prima
            - { name: kernel.event_listener, event: kernel.view, method: onKernelView, priority: 10 }
TagUso
kernel.event_listenerUn metodo su un evento specifico
kernel.event_subscriberLa classe dichiara da sé gli eventi (getSubscribedEvents())
doctrine.event_listenerEventi Doctrine su tutte le entità (onFlush, postFlush…)
doctrine.orm.entity_listenerEventi su una entità: chiavi entity ed event

Eventi Doctrine più usati

EventoNota
prePersistPrima dell'insert; l'id non esiste ancora
postPersistDopo l'insert; id disponibile. Niente flush() qui dentro
preUpdateSolo campi già mappati; niente nuove entità
postRemoveDopo la delete: tipico per ripulire file collegati
onFlushPotente e pericoloso: sei dentro l'Unit of Work

Decorazione

    Algoritma\Bundle\TrainingBundle\Provider\ShoutingGreetingProvider:
        decorates: Algoritma\Bundle\TrainingBundle\Provider\GreetingProvider
        arguments:
            - '@.inner'

    # con priorità, quando più decoratori insistono sullo stesso servizio
    Algoritma\Bundle\TrainingBundle\Provider\Other:
        decorates: some.service
        decoration_priority: 10
        arguments: [ '@.inner' ]

    # non fallire se il servizio decorato non esiste (es. bundle opzionale)
    Algoritma\Bundle\TrainingBundle\Provider\Maybe:
        decorates: optional.service
        decoration_on_invalid: ignore
        arguments: [ '@.inner' ]

Compiler pass

class AlgoritmaTrainingBundle extends Bundle
{
    #[\Override]
    public function build(ContainerBuilder $container): void
    {
        parent::build($container);
        $container->addCompilerPass(new MyPass());
    }
}

class MyPass implements CompilerPassInterface
{
    public function process(ContainerBuilder $container): void
    {
        if (!$container->hasDefinition('some.core.service')) {
            return;                     // sempre: il bundle potrebbe non esserci
        }

        $definition = $container->getDefinition('some.core.service');
        $definition->replaceArgument(0, new Reference('algoritma_training.my_replacement'));
    }
}

Come si cerca il punto di aggancio

# tutti gli eventi e i loro listener
orobox console debug:event-dispatcher

# un evento specifico
orobox console debug:event-dispatcher oro_datagrid.datagrid.build.after.users-grid

# trovare il servizio giusto
orobox console debug:container greeting

# scheda di un servizio: argomenti, tag, chi lo usa (riga Usages)
orobox console debug:container 'Algoritma\Bundle\TrainingBundle\Provider\GreetingProvider'

# tutti i servizi con un tag
orobox console debug:container --tag=kernel.event_listener

# dove il core lancia eventi
grep -rn "dispatch(" vendor/oro/commerce/src/Oro/Bundle/OrderBundle/ | head -20

Errori frequenti

SintomoCausa
Il listener non scattaNome evento errato, tag mancante, o manca cache:clear
Il listener scatta su tutte le griglieManca il suffisso .<nome-griglia> nell'evento
Circular reference detectedIl decoratore inietta il servizio decorato con l'id originale invece di '@.inner'
Metodo non trovato dopo la decorazioneLa classe decoratrice non implementa l'intera interfaccia
Il compiler pass non fa nullaManca build() nella classe del bundle, o il pass gira prima che il servizio esista
Il template override viene ignoratoPercorso sbagliato sotto templates/bundles/, o nome bundle errato
