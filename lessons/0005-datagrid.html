Formazione OroCommerce · Lezione 05

Datagrid

La griglia dichiarativa di Oro: una query, delle colonne, dei filtri — e una pagina di elenco completa senza scrivere JavaScript.

Durata: ~60 min Prerequisiti: Lezione 4 Obiettivo: elenco filtrabile con azioni di riga

Perché si parte da qui

Nel back-office di Oro quasi ogni elenco è un datagrid. Quando integri un ERP, la griglia è lo strumento con cui l'operatore capisce cosa è andato storto: quali codici non sono mappati, quali record non si sincronizzano da tre giorni. Saperla scrivere bene vale più di dieci pagine custom.

L'idea è la stessa — una griglia descritta in configurazione — ma in Oro la query vive dentro la configurazione, in forma dichiarativa, invece di stare in una classe DataProvider.

Dove vive la configurazione

ContestoPercorso del file
Back-office (admin)Resources/config/oro/datagrids.yml
Storefront (tema)Resources/views/layouts/<tema>/config/datagrids.yml

Cambio della 7.0 da tenere a mente

Le griglie dello storefront sono definite a livello di tema, non in config/oro/. Se cerchi un esempio storefront, guarda per esempio vendor/oro/commerce/src/Oro/Bundle/ProductBundle/Resources/views/layouts/default/config/datagrids.yml. Molti articoli scritti per le versioni precedenti mostrano ancora tutto in config/oro/datagrids.yml: per lo storefront è la posizione sbagliata.

Perché il tema abbia una cartella layouts/ con dentro la configurazione lo vedi nella lezione 14: lo storefront ha un motore di rendering suo. Per oggi basta sapere che quella è la posizione giusta.

Anatomia di un datagrid

Sei sezioni, e le userai sempre nello stesso ordine mentale.

SezioneRisponde alla domanda
sourceDa dove arrivano i dati? (tipo orm + query dichiarativa)
columnsCosa vede l'utente, e come è formattato
sortersSu cosa può ordinare, e qual è l'ordinamento iniziale
filtersSu cosa può filtrare, e con che tipo di controllo
propertiesValori non visibili usati dalle azioni (tipicamente URL)
actionsCosa può fare su una riga, e con quale permesso

Più due chiavi trasversali: acl_resource, che protegge l'intera griglia, e options, per il comportamento (paginazione, testo di aiuto).

Modello reale completo e leggibile: vendor/oro/platform/src/Oro/Bundle/TagBundle/Resources/config/oro/datagrids.yml, griglia tag-grid. Ha query con join, colonna calcolata, filtri di tre tipi e tre azioni.

Pratica: la griglia delle mappature ERP

  1. La configurazione. Resources/config/oro/datagrids.yml:

    datagrids:
    algoritma-erp-mapping-grid:
        options:
            entityHint: mappature ERP
        acl_resource: algoritma_erp_mapping_view
        source:
            type: orm
            query:
                select:
                    - m.id
                    - m.erpCode
                    - m.oroSku
                    - m.syncedAt
                from:
                    - { table: Algoritma\Bundle\TrainingBundle\Entity\ErpMapping, alias: m }
        columns:
            erpCode:
                label: Codice ERP
                type: field
                frontend_type: string
            oroSku:
                label: SKU Oro
                type: field
                frontend_type: string
            syncedAt:
                label: Ultima sincronizzazione
                type: field
                frontend_type: datetime
        sorters:
            columns:
                erpCode:
                    data_name: m.erpCode
                syncedAt:
                    data_name: m.syncedAt
            default:
                syncedAt: DESC
        filters:
            columns:
                erpCode:
                    type: string
                    data_name: m.erpCode
                syncedAt:
                    type: datetime
                    data_name: m.syncedAt
        properties:
            id: ~
            update_link:
                type: url
                route: algoritma_erp_mapping_update
                params:
                    - id
        actions:
            update:
                type: navigate
                label: Modifica
                link: update_link
                icon: pencil-square-o
                rowAction: true

    Nella query si usa DQL dichiarativo: entità e proprietà (m.erpCode), non tabelle e colonne. È lo stesso linguaggio del QueryBuilder della lezione 3, scritto in YAML.

  2. Il permesso. La griglia dichiara acl_resource: algoritma_erp_mapping_view, che ancora non esiste: lo creiamo nella lezione 6. Per far girare la griglia adesso, togli temporaneamente quella riga — e rimettila appena avremo gli ACL. Lasciare griglie senza acl_resource in un progetto reale è un errore di sicurezza, non una scorciatoia accettabile.

  3. La pagina di elenco. Aggiungi l'azione al controller della lezione 4:

    #[Route(path: '/', name: 'algoritma_erp_mapping_index')]
#[Template('@AlgoritmaTraining/ErpMapping/index.html.twig')]
public function indexAction(): array
{
    return ['entity_class' => ErpMapping::class];
}

    E il template Resources/views/ErpMapping/index.html.twig:

    {% extends '@OroUI/actions/index.html.twig' %}
{% import '@OroUI/macros.html.twig' as UI %}

{% set gridName = 'algoritma-erp-mapping-grid' %}
{% set pageTitle = 'Mappature ERP' %}

{% block navButtons %}
    {{ UI.addButton({
        'path': path('algoritma_erp_mapping_create'),
        'entity_label': 'mappatura ERP'
    }) }}
{% endblock %}

    Quattro righe utili: gridName è tutto quello che serve perché @OroUI/actions/index.html.twig renderizzi la griglia, con paginazione, filtri e ordinamenti già funzionanti.

  4. La voce di menu. Resources/config/oro/navigation.yml:

    navigation:
    menu_config:
        items:
            algoritma_erp_mapping_list:
                label: Mappature ERP
                route: algoritma_erp_mapping_index
                extras:
                    routes: ['algoritma_erp_mapping_*']
            tree:
                application_menu:
                    children:
                        system_tab:
                            children:
                                algoritma_erp_mapping_list: ~

    La chiave extras.routes serve a tenere la voce evidenziata anche nelle pagine di creazione e modifica.

  5. Prova.

    orobox console cache:clear
orobox console debug:router | grep algoritma_erp_mapping_index

    Poi apri https://<dominio>:<porta>/admin/algoritma/erp-mapping/. Crea due o tre record dalla pagina della lezione 4 e verifica: ordinamento sulle colonne dichiarate, filtro testuale sul codice ERP, click sulla riga che porta alla modifica.

La vittoria di oggi

Un elenco filtrabile, ordinabile, paginato, con azione di riga, scritto interamente in YAML. È il motivo per cui in Oro conviene descrivere invece di programmare: la griglia che hai appena fatto ha già l'esportazione, la scelta delle colonne visibili e la memoria dei filtri per utente.

Le cose che si rompono

SintomoCausa quasi certa
Griglia vuota ma nessun erroreAlias della query sbagliato, o filtro con data_name che non corrisponde al select.
Grid "..." configuration not foundNome della griglia diverso fra datagrids.yml e gridName nel template; oppure manca cache:clear.
Colonna che non si ordinaLa colonna esiste in columns ma non in sorters: sono elenchi separati, di proposito.
Azione che non compareacl_resource dell'azione punta a un permesso che l'utente non ha, o che non esiste.
Colonna calcolata che non filtraServe filter_by_having: true, come nella colonna usage di tag-grid.

Verifica: rispondi a memoria

Dove si definisce una griglia del back-office?

Back-office: config/oro/datagrids.yml. Le griglie dello storefront, dalla 7.0, stanno invece nel tema: Resources/views/layouts/<tema>/config/datagrids.yml.

Nella sezione source della griglia, come nomini i campi?

La query del datagrid è DQL dichiarativo: m.erpCode, con from che nomina la classe entità. Stessa logica del QueryBuilder, sintassi YAML.

Cosa serve nel template perché la griglia compaia?

{% set gridName = '...' %} ed {% extends '@OroUI/actions/index.html.twig' %}. Il caricamento dei dati avviene via richieste proprie della griglia: il controller non passa le righe.

A cosa serve la sezione properties di un datagrid?

In properties stanno i valori calcolati per riga — tipicamente type: url con rotta e parametri — che poi le actions usano tramite link:.

A memoria: le sei sezioni di un datagrid e la domanda a cui risponde ciascuna.

source da dove vengono i dati · columns cosa si vede · sorters su cosa si ordina · filters su cosa si filtra · properties valori di servizio per le azioni · actions cosa si fa su una riga. Più acl_resource per proteggere la griglia.

Ripasso dalla lezione 4 (spaziatura): cosa fa UpdateHandlerFacade::update() al posto tuo?

Intercetta il submit, valida, salva con flush, mette il messaggio flash e fa il redirect giusto (anche per i form aperti in dialog). Restituisce l'array per il template quando il form non è stato inviato.

Da leggere prima della prossima lezione

Fonte primaria

Il file vendor/oro/platform/src/Oro/Bundle/TagBundle/Resources/config/oro/datagrids.yml, letto riga per riga insieme alla pagina Entities → Data Grids della documentazione. Per i datagrid il core è più istruttivo della documentazione: contiene i casi veri (join, colonne calcolate, azioni condizionali).

Esercizio fra una sessione e l'altra

  1. Aggiungi una colonna calcolata synced che mostri «Sì»/«No»: usa type: twig, frontend_type: html e un piccolo template in Resources/views/ErpMapping/Datagrid/Property/synced.html.twig. Modello: la colonna backgroundColor di tag-grid.
  2. Aggiungi un filtro boolean «solo mai sincronizzati». Suggerimento: serve una colonna calcolata nel select — è il punto in cui capirai filter_by_having.
  3. Aggiungi l'azione delete. Cercherà una rotta di cancellazione: prova prima a capire dal core come la ottengono gli altri bundle, e portami la tua ipotesi.
