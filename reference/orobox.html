Comandi orobox

Il ciclo di vita di un ambiente Oro locale, in una pagina. Pensata per essere stampata e tenuta accanto alla tastiera.

Fonte: orobox --help (v. installata in ~/.local/bin/orobox) Progetto: algoritma-dev/orobox

Ciclo di vita

FaseComandoCosa fa
Scaffoldorobox create project <path> -v 7.0Clona l'albero dei sorgenti dell'applicazione. Non tocca Docker. Default versione: 6.1 — specifica sempre -v.
Scaffoldorobox create bundle 'Acme\Bundle\FooBundle'Genera lo scheletro di un bundle. Dentro un progetto finisce in src/Acme/Bundle/FooBundle/, già in autoload.
Provisioningorobox init -t project -v 7.0Genera configurazione e file Docker Compose, installa i vendor ed esegue l'installazione di Oro.
Avvioorobox upAvvia l'ambiente. --rebuild ricostruisce l'immagine ignorando la cache Docker; -c pulisce prima di partire.
Stoporobox downSpegne l'ambiente lasciando i dati.
Resetorobox clearRimuove container e volumi. Riparte da zero: perdi il database.

Lavoro quotidiano

ComandoUso
orobox console <cmd>Esegue bin/console nel container dell'applicazione. Il comando che userai di più.
orobox shell [servizio]Shell interattiva dentro un container.
orobox logsLog dell'ambiente.
orobox xdebugAttiva, disattiva o mostra lo stato di Xdebug (web, CLI, consumer, cron).
orobox db backup / orobox db restoreDump e ripristino del database. Da fare prima di ogni esperimento distruttivo.
orobox run <nome>Esegue un comando personalizzato definito nella sezione commands di .orobox.yaml.

Qualità e test

ComandoUso
orobox qa-initInstalla e configura la toolchain QA nel progetto o nel bundle.
orobox qaEsegue PHPStan, Rector, PHP-CS-Fixer, Twig-CS-Fixer, ESLint, Stylelint.
orobox test-initInizializza o azzera l'ambiente di test.
orobox test -f <filtro>Esegue PHPUnit. -t per una specifica testsuite, --report gitlab per il report JUnit.

Flag globali utili

  • -d, --debug — mostra tutto l'output Docker. Prima cosa da aggiungere quando un comando fallisce senza spiegazioni.
  • --config <file> — usa un file di configurazione diverso da .orobox.yaml.
  • --agent — output minimo, pensato per chiamanti automatici.

Il file .orobox.yaml

Descrive l'ambiente del progetto: versione Oro, dominio locale e document root, servizi opzionali (Redis, Mailpit, RabbitMQ, Elasticsearch, Adminer…), impostazioni dei test e comandi personalizzati. È il primo file da leggere quando entri in un progetto Oro altrui.

type: project
oro_version: "7.0"
domains:
    - host: oro.demo
      root: public
      ssl: true
services:
    mailpit: true
    redis: false
    elasticsearch: false

Attenzione

oro_version in .orobox.yaml è una dichiarazione dell'ambiente, non una garanzia sul codice. La verità sulla versione dell'applicazione sta in composer.json e composer.lock. Controlla sempre entrambi.
